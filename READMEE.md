# Уровень доступа к данным (Data Access Object — DAO)

Лабораторная работа по дисциплине **Технологии программирования**.

Тема: **Архитектурный паттерн DAO (Data Access Object) и постоянство данных**

## Описание

Приложение реализует уровень абстракции для работы с постоянными данными (хранилищем) на примере сущностей системы (например, задач/заказов). Шаблон DAO позволяет полностью отделить бизнес-логику приложения от технических деталей работы с файловой системой (JSON/CSV) или базами данных, обеспечивая выполнение стандартных CRUD-операций (Create, Read, Update, Delete).

## Архитектурный шаблон DAO в проекте

Шаблон разделяет приложение на независимые уровни, изолируя механизм работы с хранилищем:

- **Бизнес-логика (Business Logic):** контроллеры или сервисы приложения, которые вызывают методы интерфейса DAO (например, `getAllTasks()`), вообще не зная, где именно хранятся данные — в оперативной памяти, в текстовом файле или в облачной базе данных.
    
- **Интерфейс DAO (интерфейс):** контракт, описывающий доступные операции с данными (получение, сохранение, удаление).
    
- **Реализация DAO (реализация):** конкретный класс (например, `JsonTaskDAO`), содержащий технический код для работы с файлами, парсинга JSON-структур или отправки SQL-запросов.
    
- **Источник данных (source):** файлы конфигурации и хранения данных в формате JSON/CSV.
    

**Преимущество:** если формат хранения данных изменится с JSON-файлов на базу данных PostgreSQL, достаточно будет написать новый класс для реализации интерфейса DAO. При этом код контроллеров и бизнес-логика останутся абсолютно нетронутыми.

## Ключевые классы

### Задача — бизнес-модель данных

Обычный Java-объект (POJO), инкапсулирующий свойства системного объекта.

Java

```
public class Task {
    private int id;
    private String title;
    private String description;
    private boolean isCompleted;

    // Конструкторы, геттеры, сеттеры
}
```

### TaskDAO — интерфейс уровня данных

Задает абстрактный набор методов для работы с сущностями, изолируя логику сохранения.

Java

```
public interface TaskDAO {
    void save(Task task);
    Task findById(int id);
    List<Task> getAll();
    void delete(int id);
}
```

## Алгоритмы работы уровня персистентности

### Жизненный цикл операции сохранения (Create/Update):

1. Контроллер получает данные из полей ввода пользовательского интерфейса и создает объект `Task`.
    
2. Контроллер вызывает абстрактный метод `taskDAO.save(task)`.
    
3. Реализация `JsonTaskDAO` считывает текущий массив из файла `tasks.json`.
    
4. Объект преобразуется в строку в формате JSON и перезаписывает структуру в файле на диске.
    

## Диаграмма вариантов использования системы

### Сценарий прецедента: добавление новой записи

|**Поле**|**Описание**|
|---|---|
|**Название**|Добавление новой записи (задачи/заказа)|
|**Актор**|Пользователь|
|**Цель**|Внесите новые данные в систему с гарантией их сохранения на жестком диске|
|**Предусловие**|Приложение запущено, открыта форма добавления записи|
|**Постусловие**|Данные сохранены в файл, таблица на экране обновилась|

### Основной сценарий

|**№**|**Действие**|
|---|---|
|**1**|Пользователь заполняет текстовые поля формы и нажимает кнопку «Добавить».|
|**2**|`HelloController` собирает текст из полей и проверяет его корректность.|
|**3**|Контроллер создает объект `Task` и отправляет его в метод `taskDAO.save(task)`.|
|**4**|Класс `JsonTaskDAO` открывает поток записи в файл `tasks.json`.|
|**5**|Объект сериализуется, данные физически сохраняются на диске.|
|**6**|Контроллер вызывает метод `taskDAO.getAll()` для получения актуального списка и обновляет интерфейс (`TableView`).|

### Альтернативный сценарий

|**№**|**Действие**|
|---|---|
|**4а**|Файл `tasks.json` заблокирован или отсутствует доступ к диску $\rightarrow$ Система перехватывает исключение `IOException`, выводит сообщение об ошибке пользователю во всплывающем окне, данные в памяти не искажаются.|
